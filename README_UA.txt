# HOME PRIME — автоматичне оновлення наявності через три прайси

## Що робить цей пакет
- Завантажує три YML/XML прайси.
- Зіставляє товари тільки з `whitelist_prom.csv`, сформованим із твого експорту Prom.
- Вихідний YML містить тільки дозволені позиції з наявним `Ідентифікатор_товару` Prom.
- `offer id` береться з `Ідентифікатор_товару` Prom, не з ID постачальника.
- Якщо товар є хоча б в одного постачальника — available=true.
- Якщо знайдений у постачальників і всі кажуть «немає» — available=false.
- Якщо не знайдений ніде або код неоднозначний у прайсі — товар пропускається, статус не змінюється.
- KNE65 і LY-1122 виключені.
- Повторні коди в каталозі Prom та рядки без Prom ID не активовані в whitelist.

## Важливі обмеження перед підключенням
1. Це підготовлений пакет, а не вже розгорнутий сервіс. Я не маю доступу до твого GitHub-акаунта, щоб створити репозиторій або опублікувати URL.
2. У вихідному експорті Prom 127 позицій не мають `Ідентифікатор_товару`; їх не можна безпечно додати до YML за ID, тому вони не включені автоматично.
3. 57 артикулів повторюються в самому експорті Prom (114 рядків); вони позначені для ручної перевірки та не включені.
4. Відповідно, whitelist зараз містить 718 рядків зі статусом `ДОЗВОЛЕНО`. Це не означає, що всі вони вже перевірені на сумісність YML-імпорту.
5. Перед регулярним імпортом треба зробити тест вручну з 1–3 товарами та переконатися, що Prom оновлює саме існуючі картки за `offer id`. Не вмикай періодичне завантаження, доки цей тест не пройшов.
6. Періодичний імпорт Prom має окремі правила. За довідкою Prom, нові товари можуть створюватися під час нічного оновлення URL-файлу. Тому тут важливо, щоб у YML були тільки існуючі Prom ID; сам прапорець «Тільки оновлення» для періодичного імпорту не зберігається.

## Як запустити через GitHub без командного рядка
1. Створи окремий **публічний** репозиторій GitHub, наприклад `home-prime-stock-sync`. Публічний потрібен, щоб Prom міг прочитати статичний URL GitHub Pages.
2. Завантаж у корінь репозиторію `build_feed.py` і `whitelist_prom.csv`.
3. Створи папку `.github/workflows/` та завантаж туди `update.yml` (у GitHub можна створити файл з повним шляхом).
4. У Settings → Pages вибери Build and deployment: GitHub Actions.
5. У вкладці Actions вручну запусти workflow `HOME PRIME stock feed`.
6. Після успішного запуску URL буде `https://<твій-логін>.github.io/<назва-репозиторію>/prom-feed.xml`.
7. Спочатку відкрий цей URL у браузері та перевір, що файл XML відкривається. Потім додай його в Prom як URL-імпорт.
8. Спочатку ручний тест імпорту на 1–3 позиціях, з налаштуванням оновлювати тільки «Наявність». Не позначай відсутні в файлі товари як видалені/приховані.

## Як додавати нові товари
Додавай рядок у `whitelist_prom.csv` тільки після власного ручного відбору. Для нового рядка потрібні:
- `Код_товару` — код саме з Prom, що збігається з кодом постачальника;
- `Ідентифікатор_товару` — Prom ID з експорту;
- назва і `Ідентифікатор_підрозділу` з експорту;
- `Статус_підключення` = `ДОЗВОЛЕНО` лише після перевірки унікальності коду.

## Примітка
Це перша безпечна заготовка. Схеми трьох живих URL ще потрібно перевірити запуском workflow; якщо якийсь постачальник змінив формат або поле коду/наявності, звіт покаже помилку і новий feed не слід підключати до Prom.
